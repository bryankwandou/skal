The vault

The schedule is the address

The vault keeps no state account. Its vesting schedule is hashed into the seeds of a program-derived address, so the rules cannot be edited, only proven.

Derive

PDA(dest_token, total ‖ start ‖ end). Change one number and you get a different address that holds nothing.

Compute

At call time the program reads the validator clock and computes how much is still locked, without 128-bit arithmetic.

Release

It signs one Token-2022 TransferChecked for balance − locked. Anyone may call it; tokens only go to the destination baked into the seeds.

Freeze the code

After deployment the upgrade authority is set to none with --final. Not even the creator can change the rules.

// vault/src/lib.rs — the whole release rule
fn vested(total: u64, start: i64, end: i64, t: i64) -> u64 {
    if t >= end { total }
    else if t <= start { 0 }
    else {
        let d = (end - start) as u64;
        let e = (t - start) as u64;
        (total / d) * e + (total % d) * e / d
    }
}

// Release = balance − (total − vested(now))
// Signed by PDA([dest, total‖start‖end], bump)
// Token program pinned to Token-2022
