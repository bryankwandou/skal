How the vault works

The schedule is baked into the address

The vault stores nothing. Its address is computed from the release schedule and the destination wallet. Change one number and you are talking to an empty address that cannot sign for anything.

No admin, no owner

There is no signer to set and no account that holds settings. Nobody has a key to this vault, including the person who wrote it.

Anyone can trigger it

If the creator disappears, anyone can call release. The tokens still only travel to the wallet written into the address.

Frozen after deploy

Once live on mainnet, the upgrade key is thrown away with one command. After that nobody can edit the rules.

Why your wallet shows warnings

Low liquidity

True. The pool holds SKAL but very little SOL, because no SOL was deposited at launch. Selling is limited to the SOL that buyers have put in. The live counters above show both sides.

Unverified token

True. SKAL has not been through Jupiter's verification yet. Verification is a listing review, not a code check; the code checks are on this page.

Missing file metadata

True, and permanent. Name and symbol live on the mint itself, but the link to an off-chain logo file was left empty and the key that could change it was destroyed. Wallets show a placeholder icon.

Cost

Token, vault and pool for 0.0377 SOL

Solana charges rent for every byte an account occupies, so a smaller program is a cheaper one. The vault was written without a framework and trimmed to 2,472 bytes. The pool costs only rent: Meteora charges no creation fee, and no SOL was deposited.

Questions people ask

Is SKAL an investment?

No. SKAL is an educational project. It raises no money, promises no return, and has no team selling it to you. It exists to show what a token looks like when the usual ways of cheating holders are removed in code.

Why the name Save Kalimantan?

Kalimantan's forests and its hornbill, the bird in the logo, are a reminder that some things deserve protection from short-term extraction. The project is not affiliated with any organization working there.

What stops the creator from changing the vault later?

On mainnet the upgrade key is set to none right after deployment, and from then on the code is fixed. You can confirm it with solana program show, which reports the authority as none.

What if the creator loses interest?

Nothing breaks. Anyone can call release, and tokens can only go to the wallet that is part of the vault's address.

Can the creator remove the liquidity?

No. The pool position was permanently locked in the same transaction that created the pool. The creator can still claim the 1% swap fees it earns, but the SKAL and SOL in the pool can only leave through trades.

Has it been audited?

Not by a third party. The vault is 143 lines so it can be read in one sitting, the test suite covers each known attack, and the attack lab above lets you rerun those attacks yourself.
